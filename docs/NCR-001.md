# NCR-001 — A reflective Ground: a task-generated processor interprets its interpreter

**November 20, 2026 — executable mathematical experiment.** This is bounded same-language reflection, not universal self-hosting or hardware-independent computation.

## Question

Can a task whose *invariants generate its processor operations* also acquire an **executable description of the evaluator** for its own task-derived language, and use that evaluator to interpret itself? Crucially, does the interpretation hold by executing actual code in the language rather than by adding a magical `eval` opcode?

## Constructive layers

1. **Intention/invariants:** Existing NCI-001 accepts geometry, safety, goal, observable-label and symmetry contracts and constructs valid transition laws.
2. **Endogenous execution algebra:** NCS-001 closes canonical laws under composition into a finite task-relative transformation monoid `M` acting on qualified task states `Q`. Its 5x5 fixture has 16 generator laws and 29 distinct semantic operators. The source contract and every operation are independently audited.
3. **A specified *reflective* data language:** NCR-001 admits literal tuples, argument access, lazy conditionals, function calls, and seven data operations: equality, first, rest, cons, emptiness, indexing, and a verified **task-table lookup**. This is a finite explicitly supplied representation/evaluation seed; these seven operations were **not** derived from the user's task. Task operators *within* it are derived from the NCI/NCS Ground.
4. **Reflective code as data:** `compile_reflector()` emits a six-function interpreter **in exactly the same expression language** it interprets. Its source is an ordinary immutable tuple AST, not Python source or a closure. It uses source-language `if`, `prim`, and `call` nodes to decode syntax and execute primitives, and contains no `eval` primitive or privileged interpreter dispatch instruction.
5. **Self interpretation:** Feed that interpreter its own AST, its own entry function and a task program as ordinary data. A language interpreter then executes the interpreter as it interprets the task program.

With `P` the constructed task program, `E` the source-encoded evaluator and `H` the small host-language operational semantics, a concrete test checks the commuting diagram:

```
    H(P, input) = H(E, (P, "main", input, M))
                = H(E, (E, "run", (P, "main", input, M), M))
                = task-ground table evaluation of P on input
```

The second `E` in the last call is **ordinary quoted source data**; execution invokes the interpreter's own `lookup`, `evaluate`, `perform` and `invoke` functions. This is genuinely two levels of bounded interpretation. The host still realizes every step.

## Deterministic results

For the 5×5 task Ground and the three-opcode word `(0,1,2)`, the exact result agrees across these implementations. The actual AST evaluation steps depend on interpretation depth:

| Construction/execution | AST evaluation steps |
| --- | ---: |
| Direct source program through the host language | 37 |
| Task program interpreted through `E` | 1,747 |
| `E` executing the source of `E` executing the task program | 73,987 |

The authoritative values are emitted by `python reflective_demo.py`, and its receipt includes the exact host step count for each depth, so costs are never disguised as free. This is **not** a performance optimization: reflection is expensive. The separate NCS monoid can collapse the task's instruction word into a semantic macro-opcode and power that operator to extremely distant logical coordinates with logarithmic composition after construction; that is a **different** pathway with different accounted costs.

The same evaluator source works for the 3×3 Ground (4 semantic opcodes) and 5×5 Ground (29 opcodes). This demonstrates an invariant-derived *payload* with a reusable interpretation mechanism; it does **not** show that the reflective host language is synthesized from no prior semantic rules.

## Independent evidence and refusal

- Producer `reflective_ground.py` uses recursive evaluation with a bounded fuel counter and derives source program data from verified NCS algebra.
- Verifier `reflective_verify.py` re-evaluates the same AST language using an **explicit continuation stack** and an independently coded implementation of each primitive. It recomputes the direct, single-interpreted and twice-interpreted results and the exact evaluation-step count, and compares all of them against the task's semantic operator tables. It first independently revalidates the NCI/NCS mathematical Ground.
- `reflective_wire.py` uses the existing strict canonical JSON receipt envelope, and requires the receiving observer to supply a trusted source Ground. Digest editing is detected by semantic reconstruction, not by a self-authored SHA-256 alone.
- Tests refuse invalid source instructions, negative opcode addresses, malformed conditions, over-budget execution, mismatched source Ground, inconsistent cost or output, and falsified interpreter digests—even if the attacker recomputes outer wire hashes.
- Recursion and fuel limits are explicit. Finite example checking **does not** establish a theorem that the evaluator handles all valid programs or that higher levels of self-interpretation terminate.
- The mathematical receipt is **not** a VGI authorization, signed E-CPU observer event, physically demonstrated effect, or assertion that substrate-free computing is possible.

## Reproduce

Requires Python 3.11+ standard library only:

```
python -m unittest discover -s tests -v
python self_space_demo.py
python reflective_demo.py
```

The deterministic JSON report records source and interpreter identities, selected task, output equality, reflective evaluation steps and separate far-coordinate monoid composition work. The matrix CI on Linux and Windows is independently checked after publication; a workflow file alone is not evidence of successful hosted execution.

## The next genuinely generative question

This result adds executable reflection to the task-generated semantic processor, but a **small external representation language remains**. The next experiment should generate the evaluator's own data manipulation operations from the task's invariant algebra or a proved conservative extension and test whether the combined system supports arbitrary encoded self-programs within explicit resource contracts. A fully independent reflective fixed point would require stronger proofs of representability, operational equivalence and admissible universal interpretation. Relevant foundations include the established [Kleene recursion theorem](https://plato.stanford.edu/entries/recursive-functions/) and [Futamura projections](https://www.cfallin.org/blog/2024/08/28/weval/). They do not confer general fast-forwarding or P=NP.
