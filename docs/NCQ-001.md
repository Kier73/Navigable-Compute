# NCQ-001 — Exact observer-relative processor construction

**Status (2026-11-20): implemented and locally tested; Linux/Windows remote CI not yet confirmed.**

## Scientific question

Can we construct the *smallest exact processor for a requested family of future observations*, even when the native machine has nonlinear byte updates? Can we synthesize a compatible initial state at a distant temporal coordinate without enumerating the global machine states or replaying the path?

For a deterministic finite-state system `(S,T)` with an observation `O:S→Y`, define

    x ~ y  iff  O(T^n(x)) = O(T^n(y)) for every nonnegative integer n.

For the supplied finite `S` and exact `T`, the quotient `S/~` is the **minimal deterministic Moore machine** that preserves all future outputs of the declared observation. Its transition is well-defined only if the partition is stable (`x~y => T(x)~T(y)`). Computing the quotient from all 256 states of a byte is an **exhaustive computation**, not learning an unobserved universal law from a sparse sample.

The requested observer may read selected masks on selected global bytes. This first implementation uses static per-byte dependence partitioning. Each `xor`, `copy`, or `swap` operation connects its source and destination bytes. Unary operations (`add_const`, `set`, `and_const`, `rotl`, `xor_const`) remain local. A factor is a byte subset closed under all byte-level read/write dependencies. `max_states` defaults to 4,096 for each *queried* factor, and the refinement and coordinate bit lengths have explicit budgets. A larger coupled factor is **refused**, not guessed.

## Concrete results

With `T(x)=x+1 (mod 256)`:

| Observed bits | Minimal future-stable states | Explanation |
|---|---:|---|
| bit 0 | 2 | parity flips, independent of carries in higher bits |
| bit 7 | 256 | the full period of upper-bit observations distinguishes all 256 phases |
| full byte | 256 | all concrete values are already distinguishable |

Importantly, an observer looking only at the **current** high bit would initially see two classes, but these are *not* transition-stable. The partition must be refined until their future behavior is also equivalent.

The deterministic deep demo uses eight independently incrementing bytes (64 state bits, 2^64 global states) and observes only three components through masks `0x01`, `0x80`, `0x0f` at coordinates near `10^33`. The construction explores **768 concrete factor states**, computes **2 + 256 + 16** observer classes, and navigates with an explicitly counted number of quotient-function compositions. It never enumerates the global 2^64 state space. The five unqueried bytes remain symbolic freedoms, represented by an exact **integer count** of valid starting states.

This is not a general 64-bit coupled nonlinear solver. Constructing the 256-state source transition table for each queried byte is deliberately counted as work. The fast navigation applies only *after* that construction.

## Reconstructable certificate

`ComponentCertificate` retains exact factor indices, observer masks, concrete-state-to-class assignment, quotient output labels, quotient successors, and SHA-256 of the complete concrete transition table. `QuotientTraceReceipt` binds the program digest, requested temporal observations, fixed-input qualifiers, one canonical initial byte array, exact count of compatible initial states, resource counts, and all component certificates.

`quotient_verify.py` deliberately does not call the quotient constructor. Its checker:

1. Recomputes *every* bounded factor's one-step behavior from the separately coded sequential interpreter.
2. Recomputes the concrete transition digest and confirms the supplied class partition preserves current output and successor class.
3. Independently derives the coarsest stable concrete partition and checks its canonical assignments and refinement rounds.
4. Checks all requested distant coordinates using **cycle decomposition**, not the builder's exponentiation-by-squaring method.
5. Enumerates local candidate initial states, reconstructs the exact count across independent factors, and checks the canonical selected state and receipt digest.

A failed check refuses the certificate. SHA-256 **does not authenticate the source observer**, guarantee physics, or replace E-CPU's authority/quorum system. A deliberate adversarial test mutates successor edges, a transition hash, class membership, requested values, and aggregate work counts.

## Why this is a new lane rather than another emulation engine

A full-state emulator always retains enough information for *every* output. NCQ-001 specializes a machine to the **observer's future distinguishability contract**. Repeated `T^n` then applies to a quotient whose cardinality depends on *what is being asked*, not merely on the original machine's byte width. It is therefore possible for two observers to use different exact processor architectures for the same original program.

The approach has roots in classical Moore minimization, Myhill–Nerode equivalence, bisimulation/congruence, and symbolic model checking—not in a new consequence of RH. Relevant prior investigation in the account is [IFS Observation Equivalence Bridge](https://github.com/Kier73/In-Formation-Space/tree/main/bridges/observation-equivalence), especially its `transition_congruence.py`. The distinct contribution here is the direct union of byte-program compilation, future-stable *minimal* observer quotient, long-coordinate navigation, global factorization, backward initial-state synthesis, exact solution counts, and self-contained checkable witnesses.

Related established literature: [Burch et al., representing circuits using partitioned transition relations](https://www.cs.cmu.edu/~emc/papers/Conference%20Papers/Representing%20Circuits%20More%20Efficiently%20in%20Symbolic%20Model%20Checking.pdf).

## Counterexamples and next research questions

- Two byte registers linked by `xor` plus nonlinear addition form a coupled 65,536-state factor, beyond the default budget. A more capable structure engine needs BDD, SAT/SMT, algebraic or tensor factorization, or explicit execution.
- A transition that erases data makes the *future* observation independent of many inputs, but a quotient preserving *all times starting at t=0* may still require many current-state distinctions. Time-scoped quotient construction is a next experiment.
- A requested output that contains many bytes necessarily costs at least the output's actual materialization work, even if its producer was described compactly.
- A small quotient does not imply its discovery was cheap. Measure admission plus verification plus transport plus requested rendering, not just map powers.
- Real streams cannot be made exact finite machines merely by fitting a quotient to limited observations. External observation needs a qualified Ground and credible provenance.
