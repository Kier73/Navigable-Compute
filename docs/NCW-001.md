# NCW-001 — Portable mathematical Ground receipts

**Executable prototype, 20 November 2026.** JSON interoperability for NCQ-001 finite observer quotients and NCL-001 constructed additive laws.

A processor description and mathematical Ground are different from an *authenticated* source observation. This module transports a deterministic, inspectable **mathematical claim** and checks it without pretending to verify the sender's identity, external physics, host recovery lineage, or E-CPU authority.

## Contract

- `encode_quotient(program, queries, receipt, fixed=()) -> bytes` refuses to serialize a failed witness. The program identity is SHA-256 of canonical `Program.encode()` and is expected from a separate trusted source on the receiving host.
- `decode_quotient(raw, trusted_program) -> (queries, fixed, receipt)` rechecks the program identity, all concrete finite transitions, future-observation congruence, minimality, canonical initial state, distant observation and the exact compatible-initial-state count using the independent verifier.
- `encode_task(program, queries, receipt)` and `decode_task(raw, trusted_program)` move **NCQ-002 task-only** certificates with a distinct scope/kind. They must never be interpreted as NCQ-001 transition-stable processors.
- `encode_law(size, queries, receipt) -> bytes` serializes the mathematical program constructed from intentions.
- `decode_law(raw) -> (queries, law)` independently enumerates per-byte law candidates and checks the entire packet against its declared grammar. An outside authority must still establish whether the mathematical description is appropriate for its source.

All messages use ASCII canonical JSON with sorted object keys and no insignificant whitespace, no duplicate keys, exact decimal strings for large integers, a fixed schema/profile, an envelope SHA-256 over the payload and a 2 MB byte quota. Queries carry their own exact temporal coordinates and byte masks; the transport does not interpret these as wall-clock times. Noncanonical or modified packets refuse.

The SHA-256 envelope is **not** a signature, trusted timestamp, network access grant, attestation, proof of RH, or authorization to execute code. A sender with control of both payload and digest can publish any bytes. The independent mathematical checker prevents accepting a false claim for the stated program and bounded transition semantics, but cannot establish who submitted it or whether an external machine was actually observed.

## Relation to adjacent repositories

- E-CPU Virtual Processor owns persistent logical processor identity, event journals and host lifecycle.
- E-CPU owns authenticated hosts, Hypervisor control, operation admission and quorum-based recovery/authority.
- VGI owns qualified interpretation and observer evidence.

This module provides an **experimental mathematical payload** for possible future incorporation into those protocols. It does not redefine or implement them. The next verification experiment should produce a receipt on one separately scheduled machine and verify it in a second process using an independently implemented parser and Ground checker (preferably another language), with source provenance and authority added explicitly by E-CPU.

## Reproduce

    python -m unittest discover -s tests -v

`tests/test_wire.py` exercises typed byte-identical roundtrips (including task-only receipts), wrong-program rejection, wrong-type rejection, altered payloads, duplicate JSON keys and noncanonical bytes.
