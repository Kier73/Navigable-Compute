# NCP-001 / NCB-001 — Construct a space of realizable processors from intention

**Research implementation, November 20, 2026.** No existing program, state trajectory,
training history, or candidate processor is an input. A typed brief describes
what a component *could* do, which outcomes must be avoided, and which final
states are intended. The system constructs a mathematical state/transition
space, discovers safe controller laws and directly addresses a particular law.

This is exact finite, factored reactive synthesis using standard backward
attractor reasoning—not a claim to have solved unrestricted program synthesis.
The important research interface is the distinction between **describing
possibility**, **proving existence**, **constructing an instance**, and
**physically realizing its effects**.

## Logical contract and quantifiers

For factor `i`, declare:

- A finite set `S_i={0,...,n_i-1}`, an allowed initial set `B_i`, a nonempty
  terminal goal set `G_i`, and a forbidden set `U_i`.
- A finite set of named operations. Each operation `a` at source state `s`
  has a *set* `R_i(s,a)` of possible successors. An empty set means the
  operation is disabled, **not** an impossibly easy vacuous success.
- All local states are observable when choosing a local action. The
  environment may choose *any* successor in the selected operation's set.
  A terminal goal state stops and remains a goal. There is no hidden assumption
  that the environment cooperates or that a physical actuator exists.

The constructed law `pi_i : S_i -> A_i` (for nonterminal winning states) must
satisfy the single, strong quantifier order:

    EXISTS one constructed law pi_i
    FOR ALL initial states s0 in B_i
    FOR ALL sequences of permitted adversarial outcomes
    the state remains safe and reaches G_i in finite logical time.

This does **not** confuse `FOR ALL origins EXISTS some path` with `EXISTS a
law FOR ALL origins and outcomes`. The former can hold while the latter is
false. The independent refused-world example preserves this distinction.

## Construct the Ground from a description, not an executable program

`brief.py` supplies a deliberately small declarative language. An
`EffectCase(first,stop,deltas,absolute)` means that, in a stated source-state
interval, an operation may reach any listed absolute destination or any
clipped relative state `s+delta`. Overlapping source cases are refused.
Missing cases disable that operation in those source states. The concrete
finite relation is *generated* from this brief; it is not an input history.

The brief is mathematical and self-contained; it is **not** inferred from
untrusted physical observations. `brief_verify.py` separately reconstructs
each required possible outcome directly from the original typed clauses and
then checks the constructed controller's finite proof.

## Exact constructive attractor

Define `W_0 = G` and iteratively compute

    W_(d+1) = W_d union { s safe : EXISTS action a with
                                R(s,a) nonempty AND R(s,a) subset of W_d }

If the admitted initial states are contained in the fixed point, a controller
exists. The least entry depth `r(s)` is a **worst-case guaranteed remaining
step count**. A valid choice at each positive-rank state has every successor
at rank at most `r(s)-1`. Each successive goal is terminal, so the process
stays safe and reaches a goal in at most `max_(s in B) r(s)` steps.

All actions attaining this rank are retained, not just the canonical first.
The product of their choice counts across winning states and factors is the
number of **factored, state-observed, rank-optimal controller tables**.
This counts program tables, not necessarily distinct observable behaviors.

A separate checker does not invoke the constructor's attractor loop. It
validates ranking inequalities, Bellman minimality (no faster permitted
choice), terminal and unsafe classes, selected action coordinate, exact
candidate-count products and the content digest. The digest is not a
signature or independent observer attestation.

### Navigation within the space of possible *processors*

`navigate_instance(ground,k)` takes an integer `0 <= k < total_laws`.
It decodes `k` using mixed-radix representation over the admissible action
choices, producing an exact *different controller architecture* when the
coordinate selects a different action table. The verifier checks that every
selected action is the action prescribed by the exact coordinate. No
candidate tables are enumerated to access `k`. Choosing another law does not
modify the original certified possibility contract.

A separate temporal coordinate `t` asks what states are reachable under a
selected controller. At `t` beyond the maximum guaranteed rank, observation
requires only the **bounded convergence prefix**, not all `t` transitions.
When a goal set has multiple members, the interpreter reports the subset
actually reachable from the initial set; it does not invent an exact single
state. These observations are conditional on all declared transitions and
state observability being correct.

## Negative witness: construction can fail even if a path exists

`certify_nonrealizable` computes a nonempty **adversarial trap** `L` containing
an allowed initial state and disjoint from the terminal goals. For every
state in `L`, every enabled safe action has **at least one** successor also
inside `L`. Another independent checker validates the obstruction using the
source relation, without attractor reconstruction. The adversary can
therefore keep at least one admitted origin out of the goal indefinitely.

A two-action example has a risky edge from state 1 to `{goal=0, trap=2}`.
An existential path to 0 exists, but no law guarantees it when the
adversary can choose 2. The constructor **refuses**. This is a mathematical
impossibility witness for the declared finite relation, not a claim that an
unobserved real-world process is impossible.

## 128-bit composed experiment

Run `python possibility_demo.py` and
`python -m unittest discover -s tests -v` from repository root.

- The description declares **32 independent components**, each with 16
  local states and three action sketches. The implicit Cartesian Ground has
  exactly **16^32 = 2^128** global states. This independence is an explicit
  premise of the description and **must not be silently inferred** for
  coupled real systems.
- Each component admits 15 possible initial states. The product initial
  set contains **15^32** states.
- Only **32*16 = 512** local states are examined by the constructor.
  The final machine is an implicit factored controller, not an explicitly
  materialized 2^128-row transition table.
- The worst-case convergence bound is **12** logical steps. At
  `t = 10^100+173` the only admissible observation is goal `0` in all 32
  components; no claim is made about time taken by a real actuator.
- A distinct valid processor is selected at **instance coordinate
  10^30+17**, checked independently and shown to reach the same guaranteed
  goal under every declared adversarial outcome.
- Adversarial regression tests include digest replacement, incorrect ranks,
  mismatched instance coordinates, unsafe successors, ambiguous clauses,
  multi-goal non-equivalence and impossible contracts.
- For every one of the **3^(3*2)=729** deterministic 3-state, 2-action
  designs, an independently enumerated set of stationary controller
  programs either confirms exact optimal ranks or produces a verified trap.

The costs are bounded in the sum of local state counts, actions and output
sizes under explicit factorization. These results do not imply efficient
construction for arbitrary coupled machines, where the representation may
exponentially expand. The large state count is descriptive, not a measured
hardware speedup.

  semantic interpretation, transport, Hypervisor admission and authority.
  `NCP-001` proves a *conditional mathematical* realization. Hosting a selected
  action in a real E-CPU path requires independent capability authorization,
  authentic observations and proof that the declared outcome relation matches
  physical behavior.

## Next: constructing laws, not just selecting from stipulated effects

1. Accept typed **intentional invariants** rather than enumerated finite
   effect clauses, discover candidate mathematical families for them, and
   construct the smallest qualified possibility space (e.g. algebraic laws,
   sparse transducer, controller, symplectic representation).
2. Compose correlated factors by verified interface assumptions, assume/
   guarantee refinement and explicit counterexamples when independence fails.
3. Synthesize an **observation policy** when internal state is hidden, keeping
   its evidence and authority distinct from inferred truth (use IFS IWI tools).
4. Export a portable, independently hosted *mathematical* certificate and
   ask E-CPU to bind each selected action to an independently admitted
   physical realization. Never treat a locally consistent law as proof that
   a physical implementation exists.
5. Optimize total build/check/host/navigation/materialization cost, not just
   logical step count. Report when representational synthesis is more
   expensive than a reference execution.

**The machine is one constructed member of a space of allowable machines.**
The goal is to discover how much of that space can be represented, navigated,
verified and ultimately realized through communication rather than through
repeated enumeration.
