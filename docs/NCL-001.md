# NCL-001 — Constructing processor laws from intended outputs

**Status: implemented and locally tested (2026-11-20).**

The first seed built initial states for supplied programs. NCQ-001 learned how to construct a different exact observer machine from one supplied program. **NCL-001 supplies no program at all.** Instead, the requester supplies the outcomes a processor must produce at specified logical times and declares a permitted *law grammar*.

The implemented grammar is intentionally elementary, exact, and expressive across any number of independent bytes:

    x_i(t) = (x_i(0) + d_i * t) mod 256.

Both the `x_i(0)` byte and the `d_i` program constant are unknown and must be constructed. A request uses complete-byte observations `(time, byte address, value)`; the current solver refuses partial masks rather than treating a few observed bits as enough to infer a full byte. The output is executable `Program` instructions, an exact starting byte array, a congruence certificate, and the **number of other full machine constructions** consistent with the request.

For each byte, subtract an anchor observation to eliminate the unknown initial value:

    (t_j-t_0) * d_i = y_j-y_0  (mod 256).

A congruence `a*d = b (mod 256)` has solutions iff `gcd(a,256)` divides `b`. When it does, the solutions specify a residue for `d` modulo `256/gcd(a,256)`. Since all the resulting moduli are powers of two, they can be intersected exactly without enumerating 256 candidates. The smallest valid `d` is selected. The corresponding initial byte follows directly from the anchor observation. Unobserved bytes are left at a canonical zero program and zero initial value while contributing `256²` possibilities each to the exact solution count.

### A revealing constraint sequence

Suppose the true law happens to be `x(0)=201`, `d=187`, and the observer gives full-byte outputs at times `T`, `T+64` and `T+128` with `T=10^43+255`. The time differences constrain `d` only modulo four, leaving **64** possible additive programs. One additional output at `T+1` fixes `d=187` and the matching `x(0)=201` uniquely.

The point is *not* that a processor inferred a physical law from four samples. The scope is an exact, declared mathematical family. The important feature is **constructive constraint accumulation**: an additional independent observation shrinks the space of admissible architectures, and the surviving architecture can be executed by the reference interpreter or navigated by its admitted structure.

An independent checker evaluates all 256 candidate constants for each byte separately, rather than using the congruence algebra employed by the constructor. It validates the program, canonical initial byte, entire observation contract, solution cardinality and digest. The global space of candidate machines would have `256^(2n)` configurations for `n` bytes; *independence* permits per-byte reconstruction without such enumeration.

### Research direction beyond this grammar

The next architecture constructor should accept a typed family of alternative laws: reversible affine maps, conditional branching, polynomial congruences, finite-field quadratic transfer operators, neural parameterized operations and exact symbolic models. It should choose a law by the observer's semantic requirements and *measured* construction/verification/realization costs, preserving multiple solutions and contradictions rather than inventing confidence from sparse witnesses.

Program synthesis and solver-guided superoptimization are established fields. This experiment does not make polynomial-time assertions about arbitrary existential Boolean constraints or P versus NP. The additional ambition lies in composing such exact *constructors* into a processor whose architecture is not fixed before its task is specified.
