# NCQ-002 — Task-scoped temporal Ground construction

**Status: executable finite-state experiment (2026-11-20). Local Python 3.13 conformance; GitHub matrix status must be checked separately.**

## The question

If only selected outputs at precisely selected logical coordinates are required, why should a synthetic processor preserve every possible intermediate or future observation? What is the **coarsest exact state representation that preserves this intention**—and what may it no longer do?

The first quotient lane [NCQ-001](NCQ-001.md) establishes all-future equivalence:

    x ~all y  iff  O(T^n(x)) = O(T^n(y)) for all n >= 0.

This is a transition congruence and gives an independently stepable minimal Moore processor. NCQ-002 changes the quantifier. For a finite list of requested observations `Q={(t_j,a_j,mask_j)}`, define:

    x ~Q y  iff  Obs_j(T^(t_j)(x)) = Obs_j(T^(t_j)(y)) for every j in Q.

Every task-equivalence class contains exactly those concrete initial states that produce the same vector of requested outputs. The quotient is **provably minimal for this query vector**: distinct classes have distinct requested output signatures. Crucially, `~Q` is not generally preserved by the transition `T`. It is not safe to advance it, ask for additional times, or claim to emulate the full machine. A different query requires a new Ground qualification.

## Exact construction

1. Audit the original byte program's read/write dependencies and split it into complete static components. No unsafe inter-component independence inference is allowed.
2. Enumerate the complete finite one-step transition of only those components mentioned by the task. The default limit is 4,096 states per queried component; the coordinate byte length is also budgeted.
3. Compute `T^t` for each required coordinate by exact function-map squaring, including nonaffine `add_const` and other byte opcodes.
4. Map each possible initial component state to its **vector of requested masked outputs**. Equal signatures are merged; distinct signatures cannot be merged without changing the task answer.
5. Construct one canonical matching initial state and the exact count of compatible global initial states, retaining unqueried components symbolically.
6. Export a receipt with the task's full coordinate/mask contract and a concrete-transition digest. The *separate* checker enumerates the original byte transitions again, uses cycle decomposition rather than squaring, reconstructs every exact requested signature, and rechecks the canonical state and count.

This constructor still does finite exhaustive work inside each queried component. It does not infer a law for an arbitrary outside process, and the receiver cannot treat the task equivalence as a reusable all-future processor.

## Discriminating cases

| One-byte program | Observer request | NCQ-001 all-future quotient | NCQ-002 task quotient |
|---|---|---:|---:|
| `set byte0 = 0` each cycle | Full byte at `t=0` | 256 | 256 |
| `set byte0 = 0` each cycle | Full byte at `t=10^66+1` | 256 | **1** |
| `add byte0, 1` each cycle | Highest bit at `t=10^37+12` | 256 | **2** |

In the second case all 256 starting bytes are compatible with the goal, and exactly one task-output signature exists. This is an information-collapse relative to the requested time and observer—not a guarantee that the real machine has one possible physical state.

NCQ-002 uses ordinary finite automata, functional graph algorithms and exact power maps. The November 20 reported RH/GRH proof and its theta-lift analogy motivate asking how representation changes reveal structure, but **provide no new theorem used in these proofs or tests**.

## Independent witness and integration

`task_quotient.py` builds the task representation. `task_verify.py` re-enumerates the source transition from the reference interpreter and evaluates each coordinate through cycle detection, not the constructor's squaring routine. Its receipt identifies the narrow scope explicitly. `wire.py` transports it with a distinct `task-scoped-quotient` discriminator and refuses attempts to decode it as NCQ-001 all-future proof.

The `Intention(observation_scope='task-only')` option enables this lane through `realize`. The default remains `all-future` for existing clients. Future E-CPU/VGI adapters must preserve scope and source authority independently. Digest integrity is not an authenticated host identity.

## New research questions

- Could a compiler derive task-level equivalence *symbolically* through backward program slicing, SAT/BDD support and constraint propagation without enumerating all concrete component states?
- For a sequence of evolving intentions, can prior task classes be refined incrementally without redoing all work or confusing old certificates with current authority?
- Which observers benefit from an all-future Ground despite its greater construction cost, versus a cheap one-time task quotient?
- Can `~Q` be compressed into a very small straight-line procedure when source states are too numerous to enumerate?
- Can observation meaning be translated from arbitrary bytes or neural hidden states into exact task signatures under E-CPU's already existing semantic-contract machinery?
