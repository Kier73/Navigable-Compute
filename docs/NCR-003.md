# NCR-003 — The observer generates the computational language

**Status:** exact finite research experiment, 20 November 2026. The source Ground
comes from NCI-001 and its operator monoid from NCS-001. The reflective AST
experiment NCR-002 remains separate. Python standard library only.

## Can required behavior determine the interpreter's vocabulary?

NCR-002 generated an interpreter within a supplied five-form syntax grammar.
NCR-003 instead asks a mathematically different question: **given only a
qualified source transformation algebra and an intention-relative observation
contract, what is the smallest semantic instruction algebra that supports
all possible program contexts without changing any admitted observation?**

The input is a finite monoid of source programs `M` (not an x86-style ISA),
whose source states were generated from geometry, symmetry, safety, and goal
invariants in NCI-001. The observer specifies only exact initial state IDs
`B` and an output label `O(s)` for every source state. These labels constitute
the intention; the generator words, quotient instructions, composition laws,
normal-form programs, and left-regular interpreter are **constructed outputs**.

Write `m·n` for first running `n`, then `m`. The equivalence relation is

    m ~ n  iff  O(a · m · b (s)) = O(a · n · b (s))
                  for every a,b in M and s in B.

Both contexts matter. The set of allowed program contexts is *exactly* the
already-qualified finite monoid, so there is no heuristic horizon bound.
Since this is a congruence, the quotient `M/~` has an unambiguous multiplication
operation. The result is the **coarsest admissible two-sided congruence** for
this finite source monoid and selected observation contract. Equivalently,
for a goal/not-goal accepting partition it is an observer-relative syntactic
monoid, a classical construction in algebraic automata theory.

### Construct without enumerating all program contexts

The constructor partitions source operations by their immediate output
signatures on `B`, then repeatedly splits blocks according to how every
source operation multiplies on **both sides**. A stable partition is a
congruence, and by induction it preserves arbitrary finite contexts. Each
iteration strictly increases the number of blocks until stable; the finite
source monoid bounds the process. A shortest-then-lexicographic search yields
canonical words for every resulting opcode. Cayley's *left regular action*

    L_m(n) = m · n

is a faithful representation of the quotient on **its own program codes**,
because `L_m(identity) = m`. It supplies the generated instruction interpreter.
It is not a universal self-interpreter for an arbitrary AST, and it does not
replace NCR-002's tested double-interpretation construction.

### Independent verification, not hash trust

`semantic_language_verify.py` uses a **different algorithm**: it enumerates
all `(before,after,initial)` combinations and reconstructs the classes from
exact source-state transformation arrays, rather than running the producer's
incremental partition-refinement algorithm. It also directly checks every
original product's quotient image, canonical shortest generator words, and
faithfulness of the regular action. SHA-256 binds a canonical JSON receipt;
this is not a digital signature or an authenticated E-CPU/VGI admission.
The source processor is itself separately verified via NCS-001.

## Discriminating results

| Ground | Full-state observer | Goal/not-goal observer | Constant observer |
|---|---:|---:|---:|
| 3×3 | 4 opcodes | 3 opcodes | 1 opcode |
| 5×5 | 29 opcodes | 5 opcodes | 1 opcode |
| 7×7 | 38 opcodes | 7 opcodes | 1 opcode (optional verification fixture) |

The five-class 5×5 goal language is a saturated progress algebra: an
instruction advances the observable progress by one step until the goal is
reached. Its opcode language does **not** have enough information to render
the exact intervening geometric position. This is safe because that position
was not requested.

For a deliberately restricted observer (initial state 0; visible states 0,2),
the 5×5 source needs **six** context-stable language classes. Considering
only left contexts, or only right contexts, yields four, which is **wrong**
for composable programs. This is a concrete falsification of naive
observation-only compression.

The generated quotient operates on itself as a finite algebra; for a source
word repeated `10^100+173` times it uses binary powering in the quotient,
not a replay of the source trajectory. Construction and checking costs are
paid first, and the source monoid itself required finite closure enumeration.

## Navigating language revisions without inventing lost information

A second constructive result defines a **one-way semantic translation** from a
richer observer-generated language to a coarser one. For source programs `x`,
the translation `π` must satisfy

    π(x · y) = π(x) · π(y)

and map every original program to its new observation-equivalence class.
The constructor checks all source operator classes. If a total translation
exists it constructs a **surjective monoid homomorphism**, including a finite
mapping of all source codes; an independent checker validates the entire
mapping and multiplication law. For the 5×5 Ground the translation chain is:

    29 exact-state instructions -> 5 goal instructions -> 1 constant instruction

The inverse is not generally available. A reverse request returns two
explicit original processor operations that the smaller language identifies
but the larger observer distinguishes. This is a *nonrefinement witness*:
mathematically no function from the smaller code space to the larger one can
recover the original semantic identity for all programs. A changed intention
may require source evidence or re-construction rather than wishful expansion.

This is strictly a **language-level mathematical** projection; it is not an
E-CPU recovery-lineage authority, physical state migration, or authenticated
new observer observation. Those should be connected using the adjacent
repositories' existing witness and authorization protocols.

## Reproduce

    python -m unittest discover -s tests -v
    python semantic_language_demo.py

The demo outputs deterministic source identities, class sizes, certificate
hashes, wire sizes, an adversarial context profile and a distant program
coordinate. Its JSON is a reproducibility record, not a physical benchmark.

## Complexity and open work

Let `N` be the number of original source operators, `S` their concrete
state count, `B` the number of admitted initial states, and `Q` the number
of derived language classes. The *constructor* costs at most `O(N^3)`
simple partition operations in the present implementation, after the source
monoid is constructed. The independent whole-context verifier evaluates up
to `N^3 · B` source observations, plus source-processor verification. Its
memory and proof artifact scale with the finite tables; the total discovery
expense does not vanish because the resulting interpreter is small.

This does not construct a general-purpose Turing-complete programming
language. Nor does it prove a minimal physical implementation, approximate
model generalization, universal fast-forwarding, or anything about P=NP.
The quotient is minimal **only** relative to the stipulated source monoid,
initial observation set and all finite contexts of that monoid. An observer
that later requests previously hidden state details must construct a richer
language or refuse.

The next research step is to derive symbolic approximations of the semantic
quotient **before constructing the entire source monoid**, with proof-driven
counterexample refinement, and to compile its regular action into the
NCR-002 reflective evaluator or into independently admitted E-CPU operator
contracts. No source code was taken from the neighboring projects.
