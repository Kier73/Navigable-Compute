# NCP-002 — Construct a jointly realizable processor from coupled intentions

**Experiment:** Description → coupled mathematical possibility relation → verified guaranteed controller → addressed alternative processor → conditional terminal observation.

**Research scope:** exact finite, fully state-observed, adversarial-outcome reactive synthesis with two kinds of cross-factor coupling: shared action resources and forbidden joint states. NCP-001's unbounded-in-product-count factored construction remains valid **only** under its independently declared factorization assumption. This experiment does not pretend correlated systems are independent.

## The discovered gap

NCP-001 already starts with a declarative brief, compiles possible effects, proves guaranteed convergence, and addresses a controller instance with mixed-radix coordinates. Its 32-factor 2^128-state example explicitly presupposes independent factors. E-CPU's IPS-001–008 chain, in parallel, synthesizes a finite mathematical Ground, qualifies execution, fences published results against host rehome and permits a resource to change state only under its own verified authority.

The adjacent problem is the **interface between desired component behavior and constrained shared resources**. Two separately realizable components are not automatically jointly realizable if both demand the same single actuator at once. Their coupling cannot be inferred from the isolated mathematical programs.

## NCP-002 source semantics

An input CoupledBrief contains:

- Two to eight original NCP-001 GroundBrief descriptions. Each has safe and goal states, initial uncertainty, and possible effects for named actions.
- Explicit SharedResource(name,capacity,claims). A claim binds one component index and action name. Each simultaneous action consumes one slot per matching claim, so a joint action requiring more than capacity is **disabled**, never accepted under an invented virtual resource.
- Exact forbidden joint state tuples in addition to component-local unsafe states. They make joint safety a first-class relation.

**No source program is an input.** The compiler uses the original NCP-001 brief compiler and expands the finite joint product only after checking an explicit maximum state and joint-action budget. It does not make a hidden independence assumption or forecast a learned trajectory.

For each safe state s, the compiler constructs the *enabled* joint action set A(s). Each chosen action has a nonempty set R(s,a) of all possible joint successor tuples, including the full Cartesian product of independently declared adversarial local successor choices. Terminal local goal factors stay in goal states while other factors finish.

A controller π must satisfy:

    EXISTS a stationary fully joint-state-observed processor law π
    FOR ALL admitted initial states s0
    FOR ALL possible environment-selected successors under π
    ALL states remain safe
    AND a terminal joint goal is reached in a bounded number of steps.

The solution is the exact finite robust backwards attractor:

    W0 = all safe joint goal states
    W_(d+1) = W_d UNION { safe s :
        EXISTS an enabled action a with
        R(s,a) != empty AND R(s,a) SUBSET W_d }

Each rank r(s) is a proof of the worst-case number of logical transitions required. The compiler retains **all rank-optimal joint actions**, not just one prescribed policy. A mixed-radix integer k directly selects another complete joint processor without enumerating all controller tables. At temporal coordinate t beyond the convergence rank, only the bounded prefix is needed to report exact terminal observations.

The coupled solver is intentionally finite and explicit. The default joint-state budget is 512, and its default joint-action product budget is 256. A source exceeding a budget is refused. Independent product Grounds involving billions of states remain in NCP-001 and require an explicit certified independence argument.

## Concrete 9-state experiment

Two independently specified three-state components have states {0,1,2}, initial state 2, terminal goal 0 and operations:

- advance: s → s−1 when s is 1 or 2;
- hold: s → s.

Each component is separately guaranteed to finish within **2 steps**. A naive independent product suggests both can advance simultaneously and finish together in 2.

But the desired system has one **shared actuator** with capacity one. Each component's advance operation claims a slot. When both are unfinished, simultaneous advance is invalid.

The coupled compiler therefore constructs a nine-state global possibility relation and a valid joint controller with **4-step** worst-case convergence. It retains alternative rank-optimal controllers. Addressing instance coordinate 1 changes the selected program table but preserves the verified goal guarantee. A requested logical observation at 10^100+173 needs only the bounded convergence prefix and reports terminal (0,0).

This is not a computational speedup relative to independent real actuators: it is discovery of the correct feasible architecture, rather than an invalid efficient one.

With actuator capacity **zero**, none of the possible joint policies can guarantee progress. The constructor refuses; certify_coupled_obstruction produces a closed adversarial trap including the initial state. The independently implemented checker verifies the original clauses, actual resource capacity, trap closure and source identity. Another negative test admits an advance action that may leave the state unchanged forever; an existential successful path does not qualify as universal success.

## Independent checker and tampering

coupled_verify.py independently reconstructs every possible effect directly from the original EffectCase clauses, without invoking the coupled constructor's joint graph or backwards-attractor code.

It checks the exact state basis, terminal/safety classes, minimal Bellman ranks, *every* optimal joint action, the mixed-radix coordinate, selected policy, convergence rank and SHA-256 digest of the entire certificate. It independently audits adversarial losing traps. Changing the source, ranks, selected action, time or capacity—even with a recomputed content digest—is refused.

SHA-256 binds mathematical descriptions, **not** trust, ownership, peer identity or a real-world ability to actuate an operation. A passing verifier is conditional on the declared transition/outcome relations faithfully representing what a qualified receiver can do.

## Important remaining frontier

1. **Compositional coupling:** avoid enumerating the entire product when interfaces can be verified through assume/guarantee proofs. Need independent certificates for interface abstraction soundness, not merely small tests.
2. **Partial observability:** the controller here observes the complete joint state. For distant or ambiguous observer-host states, synthesis must operate on belief states or maintain a proof that an observation policy is sufficient.
3. **Native realization:** construct a verified map to real receiver capabilities, durable shared resource admissions, independent mTLS receipts and per-effect fencing. If a purported actuator's actual possible outcomes differ from the description, reject or refine the Ground.
4. **Invariants as grammar:** accept a description of relationships to be preserved rather than a fully chosen list of effect clauses, and synthesize candidate law families with explicit independent counterexamples.
5. **Physical cost:** count transport, observation, state synchronization, memory and actual host work before claiming that navigating a constructed space is cheaper than replaying a path.

The ambitious long-term goal is to make the required system's description determine which mathematical spaces are worth constructing, which instances are provably possible, and which virtual or physical hosts can realize them. NCP-002 adds one missing interaction: separate components can be possible while their *joint realization* still requires a new Ground.
