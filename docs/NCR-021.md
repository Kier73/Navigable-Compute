# NCR-021 — Compile the learned interpreter

NCR-020's actual IFS-instrumented campaign exposed a useful negative result:
Linux matched workload 144 -> 72 attempts, 8.06 -> 7.49 ms; Windows matched
144 -> 84 attempts, 12.10 -> 13.81 ms. Fewer mechanisms need not mean lower
elapsed time. These are individual hosted runs, not statistical speed claims.

This increment keeps exactly the same learned choices and mathematical
mechanisms while compiling the policy itself into an indexed decision table.
The policy packet is first structurally revalidated by the existing NCR-020
reader. Group the admitted statistics by context, and choose the same minimum
mean with the same tie order once. Incomplete/unsuccessful groups default to
baseline. A mapping proxy prevents accidental table mutation.

A bound router precomputes the rule support mask and rule count of its current
Vocabulary. It shares the exact NCR-020 feature projection, which validates
request type and limits before selection. A binding checks receiver object,
parent, observations, base and learned tuple identities; any change, including
a newly learned rule, or another clock actor/segment defaults to baseline until
an explicit rebind. This is the existing trusted in-process immutable-object
discipline, not a security sandbox or remote state attestation. No source answer,
proof or witness is cached by this layer. Interpreter.realize independently
checks every result through the same existing checker.

The campaign trains a new local policy on 36 examples and tests 72 matched and
72 shifted requests. All three schedules (baseline, interpreted policy and
compiled policy) are executed on each request in rotated order, independently
reaudited outside the measured span, and checked for identical semantic
answers; the two learned versions must also choose the same strategy and
mechanism. Report training, one-time compile/bind, end-to-end timings and
separate selection-only timings for 7200 calls per workload. Training and
binding are not free. The workload is structured and timings are noisy.
No minimum speedup is required for correctness. No claim of globally optimum
schedule or arbitrary autonomous code synthesis.
